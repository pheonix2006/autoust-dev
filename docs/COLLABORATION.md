# Collaboration Rules

共同遵循 [学习工作区目录规范](workspace-layout.md) 与 [开发指南](DEVELOPMENT.md)。两个独立仓库放在一个用户选择的学习项目里。

- Canvas CLI 维护认证、SSO 续签、Canvas REST、分页、下载、稳定 JSON 与错误契约。
- AutoStudy 维护归档、来源调查、简短计划、成果验证、状态扫描和任务入口。
- 跨仓库变更先核对 CLI 的实际能力，再更新调用脚本和所有活动说明；优先通过本地 editable 安装验证。
- 用户已授权的工作持续推进；仅对真正影响结果的缺失信息询问。课程提交需要明确授权，状态扫描不自动执行所有建议作业。
- 并行工作划分文件所有权，保留已有未提交修改。每个仓库独立检查 diff、测试与 Git 状态，不自动合并历史或推送。
- 文档检查覆盖 README 各版本、AGENTS/CLAUDE/skill、任务指南、目录与脚本参数。历史记录保留当时事实并标注历史身份。
- 私人 Canvas 快照、课程材料、作业、认证信息、每日记录不进入公开提交。网络失败不等于来源不存在，身份匹配不能只凭标题。

外部参考项目与旧 staged 设计可用于研究，但不是运行依赖，也不覆盖当前 `do-homework.md`。只按本次修改运行有意义的验证，准确报告端到端覆盖范围。
